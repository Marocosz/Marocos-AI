# Plano — a janela de Serviços

Spec: [`2026-08-12-servicos-design.md`](../specs/2026-08-12-servicos-design.md).

Este arquivo não repete o desenho. Ele fixa **a ordem** e **como se verifica**,
que é o que a spec não cobre.

## A ordem, e por que ela é esta

O app precisa existir antes de a lateral do explorador poder mostrá-lo, e a
lateral aparece em quase toda captura. Logo: **todo o código primeiro, a suíte
visual por último e de uma vez só.** Rebaselinar no meio significaria rebaselinar
duas vezes as mesmas ~18 cenas.

### 1. Conteúdo (`content/servicos.js` + `i18n/os.js`)

Nenhum componente ainda. Escrever os dados nos dois idiomas e as strings de
interface. Sai daqui com `npm test` ainda passando (nada quebrou).

O `icon` de cada serviço vem do **registry**, não é escolhido no conteúdo, para os
serviços que apontam para um app usarem o mesmo glifo daquele app — é a regra que
o guia do "Sobre" já segue (`getApp(id).icon`).

### 2. Registro (`registry.js`, `xpIcons.jsx`, `system.js`, `cssBridge.js`)

Com o app registrado mas o componente ainda não escrito, `npm test` **tem de
passar** — é aqui que o contrato de `defaultSize` do chrome de explorador é
exercitado (`config/system.test.js` importa o registry e soma). Se 884×626 estiver
errado, é neste ponto que aparece, antes de qualquer CSS.

### 3. O app (`ServicesApp.jsx` + `.css`)

Ordem interna: JSX inteiro primeiro, CSS depois. O JSX define os nomes de classe
e o CSS os consome — escrever o CSS antes é escrever contra uma marcação
imaginária.

Checklist do CSS, tirado direto das regras do projeto:

- [ ] `container-type: inline-size` na raiz; consultas em `@container`, nunca `@media`
- [ ] teto `max-width: 1040px` + `margin-inline: auto` na raiz (há grade/colunas)
- [ ] nenhum `max-width` em `ch` nos parágrafos — um limite só, na raiz
- [ ] nenhuma cor literal: `rgb(var(--accent-rgb) / X)` para qualquer opacidade
- [ ] uma única superfície preenchida (a ação), com `--sup-fundo`/`--sup-borda`
- [ ] o destaque é `--sup-faixa`, não retângulo tingido
- [ ] `--win-control-radius` em tudo que é clicável
- [ ] `background-color: transparent` em `<button>` pintado só por `background-image`
- [ ] `@property` para o ângulo do gradiente cônico, se o anel de luz for usado
- [ ] sem movimento, o pulso **para**; não some

### 4. Terminal (`contact.js`, `TerminalApp.jsx`)

Só depois de o app existir, porque o ponteiro do `vps` precisa de um destino que
já esteja no registry.

### 5. Contagens e documentação

`sistema.js` (41 → 45), e o "nove/9 apps" nos seis arquivos que o citam. **No
mesmo commit da mudança**, não depois — a própria SKILL.md manda, e o mecanismo
de apodrecimento que ela descreve é exatamente "a tarefa N+k muda o código e
ninguém relê a documentação".

### 6. Verificação

```powershell
cd frontend;      npm test          # lógica pura + contrato do explorador
cd frontend;      npm run build     # não pega import dinâmico quebrado, mas pega o resto
cd frontend/visual; npm run build:frontend
cd frontend/visual; npm test
```

## O rebaseline, que é a parte perigosa

~18 cenas vão reprovar de uma vez, e **isso é o esperado** — a lateral do
explorador é derivada do registry, então os seis apps de explorador ganham a linha
"Serviços" sozinhos, mais a grade de ícones, o menu Iniciar e a home mobile.

O procedimento, e ele não tem atalho:

1. `npm run report` e abrir o relatório.
2. Conferir **cada** diff. O único pixel novo pode ser: a linha nova na lateral,
   o ícone novo na grade/menu/dock. **Nenhum ícone existente pode ter mudado de
   posição** — se mudou, a grade refluiu e isso é regressão, não ruído.
3. Só então `npm run test:update`.
4. Rodar de novo, e tem de ficar verde.

Se uma cena reprovar com um número **estável** que não se explica pela linha nova
(o caso dos 88px de rasterização de SVG que a skill documenta), parar e achar a
causa. Não subir tolerância.

## O que NÃO entra

- Nada em `backend/` — decisão do dono do projeto, o Marcos Virtual fica intocado.
- Nenhuma dependência nova no `frontend/package.json`.
- Nenhum teste com DOM: o vitest roda em `environment: 'node'`. O que precisa de
  navegador vive em `frontend/visual/`.
